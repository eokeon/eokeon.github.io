TripLinker 상세 설명

사용자 취향 분석 기반 맞춤형 여행 경로 추천 & 실시간 동행 정산 웹 플랫폼

4인 팀 | 2개월 Backend Core Java 17 Spring Boot 3 Spring AI Spring Data JPA Spring Security (OAuth2 / JWT) MariaDB AWS EC2

1. 프로젝트 개요 & 시스템 아키텍처

TripLinker는 사용자의 여행 스타일, 동행자 유형, 이동수단 및 예산 범위를 종합적으로 분석하여 최적의 여행 경로를 자동 생성하고, 실시간 동행자와의 경비 정산을 지원하는 스마트 여행 웹 플랫폼입니다. 단일 AI 모델의 가짜 장소 생성(Hallucination) 한계를 극복하기 위해 Multi-LLM 2단계 파이프라인을 자체 설계하였습니다.

주요 사용 기술 스택 (Backend & Infrastructure)
  • Core Backend: Java 17, Spring Boot 3.x, Spring Data JPA, Spring Security, Gradle
  • AI & LLM Integration: Spring AI ChatClient (@Qualifier 라우팅), Anthropic Claude 3.5 Sonnet, Groq Llama 3.3 70B, Google Gemini 1.5 Pro (Fallback)
  • Database & Caching: MariaDB, MySQL, Spring Cache
  • External APIs: Kakao Maps Javascript SDK, Kakao Mobility REST API (동선/시간 계산), 기상청 단기예보 API, Kakao/Google OAuth2
  • Infra & DevOps: AWS EC2, S3, Docker, Nginx, GitHub Actions

2. 핵심 백엔드 기능 상세 구현

① AI 멀티 LLM 라우팅 & 장애 대응 (Fallback) 시스템
  • 2단계 생성-검증 파이프라인: 속도가 빠르고 저렴한 Groq(Llama 3.3)을 통해 1차 일정을 초속 생성한 후, Claude 3.5 Sonnet이 장소 존재 여부 및 동선 파괴/예산 불일치 오류를 자동 교정하도록 구축.
  • 자동 장애 복구 (Automatic Failover): Groq 또는 Claude 호출 시 API 키 한도 초과나 네트워크 장애가 발생할 경우 Gemini 1.5 Pro로 자동 폴백되는 안전장치를 설계하여 서비스 중단 방지.
  • Structured JSON Parsing: 프롬프트 내 JSON Schema 명시 및 Jackson Custom Parser를 작성하여 99.9% 안전하게 DTO 객체로 변환.
② Kakao Mobility & 기상청 API 연동 동선 최적화
  • 실시간 거리/시간 계산: Kakao Mobility REST API를 활용해 출발지-경유지-목적지 간의 실제 차편/대중교통 이동 시간을 동적으로 계산.
  • 날씨 연동 동선 시각화: 여행 일자의 기상청 단기예보 데이터를 동기화하여 야외/실내 장소 비율을 동적으로 추천 반영.
③ 동행 일정 공유 & 실시간 자동 정산
  • UUID 공유 토큰 시스템: 고유 UUID 공유 키를 발행하여 비회원 및 동행자가 별도 회원가입 없이 링크 하나로 여행 일정을 조회하고 공동 편집 가능.
  • 실시간 1/N 자동 정산 계산기: 식비, 숙박, 교통 등 카테고리별 사용 금액을 등록하면 멤버별 정산액 및 예산 대비 지출 현황 리포트 자동 생성.
④ OAuth2 & JWT 이중 토큰 보안 시스템
  • OAuth2 소셜 로그인: Kakao, Google OAuth2 연동 및 사용자 프로필 데이터 자동 동기화.
  • Access / Refresh Dual Token: Access Token(Header, 유효기간 짧음)과 Refresh Token(HttpOnly Secure Cookie, DB 저장을 통한 무효화 관리) 구조 구현으로 XSS/CSRF 보안 강화.

3. 트러블 슈팅 & 성능 개선 (Technical Issues & Resolutions)

1. 단일 LLM 환각(Hallucination) 및 응답 지연 현상 Issue Resolved

• 문제 상황: 단일 LLM 모델만 사용할 경우 존재하지 않는 가짜 장소를 추천하거나 예산 계산에 오류가 발생하는 환각 현상 발생. 또한 고성능 모델 사용 시 응답 시간이 5~8초 이상 지연됨.

• 원인 분석: LLM의 확률적 텍스트 생성 특성 및 단일 Prompt 내 과도한 조건부 부여로 인한 모델 과부하.

• 해결 방법: Groq(초속 생성) → Claude(검증 및 교정)로 역할을 분리한 2단계 파이프라인 구축. Claude 검증 실패 시 원본을 유지하는 예외 처리 및 Gemini 폴백 추가로 생성 품질과 응답 안정성 확보.

2. Kakao Mobility API 다중 호출로 인한 병목 지연 Issue Resolved

• 문제 상황: N개의 경유지 간 이동 경로 및 시간을 계산할 때 동기(Blocking) HTTP 요청으로 처리하여 API 응답 시간이 3초 이상 지연됨.

• 원인 분석: 각 경유지 구간별 API 호출이 순차적으로 실행되어 네트워크 RTT가 중첩됨.

• 해결 방법: CompletableFuture 기반 비동기 병렬 API 호출 처리 적용 및 자주 조회되는 장소 위도/경도 데이터베이스 캐싱 전략으로 평균 응답 시간 70% 단축 (3.2s → 0.8s).

3. Refresh Token 탈취 및 세션 무효화 관리 이슈 Issue Resolved

• 문제 상황: 프론트엔드 LocalStorage에 토큰을 저장할 경우 XSS 공격에 노출될 위험 존재.

• 해결 방법: Refresh Token을 HttpOnly, SameSite=Strict 쿠키로 전환하고, DB 내 RefreshToken 엔티티를 두어 로그아웃 또는 이중 로그인 시 기존 토큰을 무효화(RTR 기법)하는 안전한 인증 체계 구축.
